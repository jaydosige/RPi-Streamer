      NDI receive

      A Pi 4 can comfortably decode NDI HX (H.264/HEVC). Full-bandwidth SpeedHQ at 1080p60 is likely beyond it — if playback stutters, switch the sender to HX or select the proxy stream above.
      These change the pipeline, so saving restarts the stream — expect a one-second black frame. If something goes wrong, Reset to defaults at the bottom puts everything back.

      Presets

      What this box can do

      Dropped frames

      On by default. The sink discards frames that arrive late so the picture stays in sync with the clock. If the Pi is only slightly too slow, this is usually the thing turning "a bit behind" into visible dropped frames — turning it off often fixes the symptom outright.
      Off means every frame is shown the moment it arrives. Motion can judder very slightly, but nothing is thrown away. For signage and IMAG that is usually the better trade.

      CPU cost

      Cheapest possible, because videoscale becomes a passthrough. It only works if your display advertises a mode matching the source exactly; if it does not, the pipeline falls back to the pinned mode.

      Buffering

      Standby screen

      What the display shows when nothing is playing. The standby screen is a live output, not the absence of one — that is what keeps the Linux console off the screen.
